      Targets

        Every host you tick gets its own run of the plan, started together as one run group; the group passes only if every one of them passes.

        Flashing needs Build: without it the boards keep their firmware, which must already be the ref's.

        Costs extra build time and needs arm-none-eabi-gcc on the target; the run then records its own firmware image, which every test that writes or checks an image needs.

        Costs another firmware build's worth of build time on top of the image above, which it asks for; the run then records the btbr image, the one ubertooth-btbr runs and nothing else does.

        Costs extra build time; builds ubertooth-btbr and ubertooth-specan-ui with python3 on the target, where specan-ui also needs numpy, qtpy and a Qt binding.

        A board keeps its bootloader through every firmware update, so recording it is all a normal run does. Check and Update need Build and arm-none-eabi-gcc on the target. Update writes flash over a debug programmer the registry pairs with the board, and fails on a stale board that has none; it also needs Flash, because the write happens before preflight and the board has to be carrying this run's firmware first.
